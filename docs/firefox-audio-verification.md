# Firefox: повторная проверка звука — 2026-11-06

Пользователь сообщил о тишине в обе стороны в Firefox. На снимке были ненулевые
переданные/полученные аудиобайты и «Уровень голоса: недоступен». Опубликованный
клиент `/assets/index-DHMSsNcJ.js` соответствовал предыдущему исправлению звонков.

Важно: ненулевые RTP-байты не доказывают наличие голоса или воспроизведение.
Исходная тишина физических устройств на тестовых устройствах не воспроизвелась:
прежний плеер также выводил тестовый тон в Firefox. Ниже описаны изменения
в тракте воспроизведения и подтверждённые проверки, а не установленная причина
тишины на устройствах пользователя.

## Изменения

- Основной вывод полученного аудио идёт через Web Audio. Контекст создаётся/
  возобновляется при действии «Позвонить»/«Ответить» и разделяется измерителем
  микрофона и плеером; удаление плеера не закрывает используемый измерителем
  контекст. Когда последний владелец освобождён, контекст закрывается.
- Обычный HTML-аудиоплеер сохранён как альтернативный способ воспроизведения.
  При переключении предыдущий путь отключается: одновременного двойного звука нет.
- Плеер вынесен из закрытого `<details>` и из видеокомпонента. Один плеер
  сохраняется в течение звонка; изменения видео при неизменной аудиодорожке
  не вызывают pause/dispose/повторный запуск аудио.
- В HTML-плеер передаётся сразу заполненный аудиопоток, а не пустой поток,
  в который дорожка добавляется после присвоения srcObject.
- Уровень микрофона измеряется локальным AnalyserNode по реальным сэмплам,
  без воспроизведения собственного микрофона. getStats остаётся запасным источником.
  Это работает и когда Firefox не возвращает media-source.audioLevel.
- Счётчики/уровень обновляются каждую секунду на активном соединении без HTTP;
  таймер и анализатор освобождаются при завершении.

## Результаты

- `npm test`: 50 тестов успешно. Включены сохранение плеера при обновлении видео,
  общий аудиоконтекст и его освобождение, переключение Web Audio/HTML, повтор
  после блокировки autoplay и обновление диагностики без серверных запросов.
- `npm run build`, `npm run lint`, `git diff --check`: успешно.
- Два отдельных участника в Firefox headless с настоящими RTCPeerConnection
  и тестовыми микрофонами: измерен ненулевой сигнал на входе и на выходе каждого
  плеера. Для Web Audio RMS выходного узла около 0.072, для HTML около 0.072.
  Вход около 0.071; это тестовый тон, не запись голоса пользователя.
- Дополнительно проверен полный React-интерфейс двух Firefox-участников
  на ширине 390: «Позвонить» → «Ответить» → установленное соединение,
  видимый плеер, ненулевой выход в обе стороны, уровень микрофона 7% вместо
  «недоступен», рост счётчиков и завершение. Выход измерялся у источника,
  подключённого к AudioContext.destination, а не только по RTP.
- В браузерных тестах HTTP-сигналинг подменялся локальными ответами, для
  ускорения UI-теста резервный таймер уменьшался только внутри браузера теста.
  Настоящий Pusher и внешние сети в этих проверках не использовались.

Слышимый звук физических устройств пользователя не подтверждён. Работа
WebKit на Windows не проверена: тестовый движок не предоставляет AudioContext.
Серверные настройки и зависимости проекта не изменялись. Новая сборка
подготовлена локально; она требует публикации перед проверкой на сайте.
