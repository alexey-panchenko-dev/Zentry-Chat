# Звонки с необязательной камерой — 2026-11-06

Начало звонка и «Ответить» запрашивают только микрофон. Камера изначально
выключена; отдельная кнопка запрашивает видео и добавляет его в текущий звонок.
Отсутствие камеры, запрет разрешения или ошибка видеоканала не завершают аудио.
Отсутствие/запрет микрофона оставляют входящий звонок без принятия и показывают
ошибку по-русски. Отключение обязательного микрофона завершает текущий звонок.

Вызывающий заранее резервирует видео в SDP. Принимающий использует видеоканал
из полученного offer: предварительное создание второго канала приводило к тому,
что включённая камера принимающего не доходила до вызывающего. Это найдено
и исправлено при проверке настоящими RTCPeerConnection в Chrome.

Дополнительно проверены и исправлены:

- Отмена ожидания разрешения на устройство при завершении звонка; поздно
  полученная дорожка останавливается и не возвращает завершённый звонок.
- Сохранение микрофона при включении/выключении камеры и отказе `replaceTrack`.
  При выключении захват камеры прекращается даже при ошибке отсоединения.
- Поздние ответы API и сигналинга старого соединения не заменяют новый звонок.
- Повторный `dispose` не дублирует завершение; после восстановления страницы
  из кэша навигации браузера подключение к уведомлениям создаётся заново.
- Аудиозвонок показывает аватар вместо пустого видео. Сообщения об ошибках
  и диагностика расположены отдельно от нижних кнопок воспроизведения/звонка.

## Результаты

- `npm test`: 46 тестов успешно, включая 18 тестов контроллера звонков.
- `npm run build`, `npm run lint`, `git diff --check`: успешно.
- Две отдельные страницы Chrome headless, настоящие WebRTC-соединения и тестовые
  медиаустройства: подтверждены ненулевые исходящие и входящие аудиобайты у обоих
  участников без запроса видео. Подтверждены получение видео при включении камеры
  каждым участником без второго offer, продолжение работы микрофона после
  выключения камеры и освобождение устройств после завершения.
- Мобильный интерфейс 390×844: «Ответить» работает при недоступной камере,
  дополнительная попытка включения камеры не завершает звонок. При отсутствии
  микрофона показана русская ошибка, запрос accept не выполняется.

В браузерных проверках HTTP-сигналинг подменялся локальными ответами, Pusher
не использовался; RTP передавался между настоящими браузерными соединениями.
Слышимый звук физических устройств, Safari/Firefox и разные сети/работа TURN
этой проверкой не подтверждаются. Серверный контракт и настройки размещения
сохранены; изменения подготовлены локально.
