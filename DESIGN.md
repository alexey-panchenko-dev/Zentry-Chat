# Zently visual integration

## Intent
Apply the user's approved Zently messenger visual identity to the existing React client. The existing Go/PostgreSQL/Pusher backend and WebRTC controller remain authoritative; media additions are authorized by docs/superpowers/plans/2026-11-06-voice-and-photos.md.

## Visual language
Dark three-panel messenger, Manrope, #0B090E background, #141116 surfaces, #211C23 cards, #FF1493 pink and #B7FF39 lime. Pink outgoing bubbles, subtle pink edge light on incoming bubbles, lime navigation and send controls. Glass is limited to composer and call controls. No blue. Initial avatars use an account username when supplied, otherwise the existing account name; contact-label aliases are not introduced.

## Tokens and ownership
Runtime visual tokens live in client/src/zently.css. Reusable Brand/Avatar are in client/src/Visual.tsx. Existing calls.ts, RemoteAudio.tsx and main.tsx remain unchanged. api.ts adds optional voice/photo fields only. CallPanel.tsx changes layout, modal focus and optional synthesized audio only; it delegates start/accept/reject/end/device actions to the original CallController.

## Supported behavior
Preserve email/password auth, original user search, pagination, message retry/idempotency, Pusher subscriptions, call polling and WebRTC media handling. This integration does not add unsupported backend capabilities or pretend that a Pusher publication is a read receipt. Mobile separates the conversation list and active chat, with a Back action. Call sound is a presentation-only preference.

## Verification
Original build, lint and four call-controller tests pass. See INTEGRATION.md for API checks, UI fixture coverage, protected-file verification and remaining gaps. Test fixtures stay outside the repository and are not shipped.

## Authorized media behavior
VoiceRecorder owns audio-only capture and bounded local drafts (120 seconds, 3 MiB). VoiceComposer owns preview/cancel/send/retry with the same UUID and preserved text. Navigation, calls, page hide and unmount release capture; late permission results stop tracks. VoiceMessage uses native audio controls for honest playback and seeking, without invented waveform data. CallPanel reports active/busy state without changing its controller.
ProfilePhoto owns JPG/PNG selection (2 MiB), preview, replacement/removal and pending/error feedback. The server validates and re-encodes photos. Avatar remains shared owner of account initials and authenticated API photos with image-error fallback. External image URLs are excluded. Existing session/query caches refresh after photo changes. Controls retain dark Manrope/pink/lime tokens and Russian labels. Native audio controls are intentionally platform-owned, keyboard accessible and responsive.

Auth and search forms own localized inline validation with first-invalid-field focus; native constraint checks are retained without browser popups. Composer textarea uses the shared resize-none rule to preserve action visibility.

The single composer surface contains the idle microphone beside the text draft and send button. Recording/requesting/preview replace the text controls within that surface; the mounted text input retains its draft and returns after send/cancel. Voice preview has only its own send action.

MediaAvailability requires explicit authenticated server capability flags from /realtime/config before mounting voice/photo controls. Missing flags, old servers and lookup errors keep uploads/recording unavailable with a compact explanation; checks repeat every 30 seconds until supported. Text and call flows retain their existing behavior.

Profile photos accept JPEG/PNG inputs up to 15 MiB. The browser prepares a proportional JPEG copy with longest edge at most 512px, without upscaling, before upload. The stored upload stays below the existing 2 MiB server/database limit. Pending preparation disables upload controls; stale preparation results and temporary object URLs are released on replacement/unmount.

## Authorized contact profiles
The contact-profiles plan authorizes membership-scoped peer details and private owner contact editing. ContactProfile is the shared native modal owner with Escape/focus restoration, cleanup, scrollable mobile content and proportional photo enlargement. Header name/avatar form one semantic button. Known name/photo remain available on old-server errors; phone/email render only fields explicitly returned by the peer-profile endpoint. ContactSettings owns international phone normalization/removal and opt-in visibility toggles (false by default); registration email remains read-only. The contact_profiles capability gates settings. Profile calls close the dialog before forwarding a unique request through CallPanel to the existing controller; consumed requests cannot repeat or queue behind an active call. No SMS verification or external service is added. Existing tokens and the dark pink/lime theme remain authoritative.

Upstream discovery, read receipts and audio-first call behavior remain intact. Contact profile calls now use the same audio-first start action (Позвонить); camera remains the existing in-call opt-in.

## Conversation controls and birth dates
The controls-and-birthdays plan authorizes actor-only history clearing and directional block/unblock through membership-checked server state. useConversationControls owns shared state, capability gating, mutation feedback and cache updates; existing personal conversation updates/focus/recovery invalidate it. Message merging filters full integer IDs at or below the clear cursor, including late realtime events. Blocking disables text/voice/profile and header call actions in both directions while preserving the text draft and idempotency state. ContactProfile reuses its native modal for explicit clear/block/unblock confirmation with cancel, pending and error states; actor-only clearing and its scope are stated. Server remains authoritative.
The own account avatar opens a dedicated profile view for photo/name/bio/city/birth date and calculated age/birthday preview. Gear settings contain contact privacy/sounds/logout. The footer button is the sole compact-menu control. DOB input is numeric DD.MM.YYYY with real calendar, leap-year,1900..today validation and ISO transport, without an age eligibility rule. Registration requires DOB and a public health birth_dates capability before signup; login remains available on older servers. Owner profile retains full DOB; peers see only server-returned MM-DD birthday and a today badge.
Own ProfilePhoto now owns the single avatar/preview and accessible photo picker button. The plus affordance appears on desktop hover/focus and remains visible on touch. File selection is hidden behind that button; prepared preview retains Save/Cancel, pending/errors and cleanup. Photo deletion is intentionally absent from this view per user preference. Unsupported servers retain the existing avatar while disabling upload.

User privacy override: login email is owner-only and appears solely in gear ContactSettings as read-only data. Email-sharing controls are removed; saves explicitly force show_email:false for legacy compatibility. ContactProfile never renders peer email even if an old server/cache supplies it. Only phone visibility remains opt-in.
## Chat image messages
Chat-image upload is capability-gated by media.chat_images. The inline photo button opens the platform file picker/gallery for JPG/PNG up to 15 MiB; a proportional JPEG copy (longest edge 1600px, quality85, at most4 MiB) is prepared locally. Avatar preparation retains its512px default. The single composer surface shows a local preview with explicit Send/Cancel, keeps text mounted, and coordinates voice/photo drafts without unmounting the recorder. Failed upload retains the identical file/UUID for retry; cancel/block/navigation abort preparation/upload, release URLs and ignore stale completion. Server remains authoritative for membership/block/clear access. Message rendering uses only authenticated same-origin message-image URLs; proportional enlargement is a native keyboard/Escape dialog. Read acknowledgements pause behind image viewing. Email remains solely in owner gear settings, never contact/photo/discovery views.
Contact profile actions now live solely in the top-right ellipsis disclosure next to Close: Delete chat, Delete contact, Block/Unblock. Native disclosure semantics provide Enter/Space/Tab; outside click/blur and Escape close it, and cancelled/completed confirmation restores focus to the disclosure. New delete/remove items require media.chat_removal; legacy chat_controls retains only block/unblock. Delete chat clears only the actor history and hides its list item; Delete contact hides only the actor list entry while preserving history and block state. Both require explicit in-dialog confirmation. Navigation/list removal occurs only after a successful hidden:true response; tagged IDs protect a newly selected peer from stale completion. Actor list caches are cancelled/filtered before refresh, and delete_chat retains the clear cursor protection against late events.
## Square avatar cropping
Avatar containers own a strict1:1 image box with bounded grid tracks, overflow clipping and cover rendering; existing rectangular avatar uploads cannot stretch grid tracks into ovals. Contact profile avatar display is square/cover too; chat image messages retain their proportional preview and1600px preparation.
ProfilePhoto validates JPG/PNG up to15 MiB, then opens AvatarCropper in the existing centered native modal/blur treatment. Users position a square crop through pointer/touch dragging or labeled horizontal/vertical sliders, with zoom1..3. Pure crop geometry clamps the source rectangle; applying renders a512×512 JPEG through source/destination canvas cropping. Apply only creates the existing local preview; Save remains explicit. Cancel restores the saved avatar, stops late preparation, releases the raw URL and restores picker focus. No image is uploaded automatically, and keyboard/Escape behavior remains native.

Contact profiles render in the body top layer; the application behind an open profile is blurred independently for browsers that omit backdrop filtering. Birthday always has a labelled row, including an honest missing-date state for older accounts.

Message receipts: one dark tick is server-saved, two dark ticks require a recipient browser acknowledgement after receiving actual envelopes; two lime ticks require the existing focused visible-chat viewport receipt. Clearing history is not reading. Incoming bubbles use an opaque graphite surface with a restrained pink edge; the chat background has a very low-contrast dot texture. Sidebar header, navigation rows and account footer keep equal vertical dimensions in both width modes; the logo is centered.
