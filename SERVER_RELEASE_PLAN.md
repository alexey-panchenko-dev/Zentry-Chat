## Изменения базы

В коде релиза относительно опубликованного репозитория добавлены миграции 031–046. Фактический перечень неприменённых миграций нужно подтвердить чтением `schema_migrations` в рабочей БД: публичный health не раскрывает её состояние.

| Номера | Назначение |
| --- | --- |
| 031–037 | Приватность, запросы на переписку, жалобы, роли, push-очередь и история авторства в группах |
| 038–042 | Устройства, 2FA, события безопасности, расписание сообщений и опросы |
| 043–045 | Настройки уведомлений, упоминания и ограничение длины токена упоминания |
| 046 | Nullable-поля миниатюр фотографий |

Миграции запускаются автоматически до открытия HTTP-сервера, в одной транзакции с блокировкой и проверкой контрольных сумм. Поэтому даже обычный запуск новой версии сервера является изменением рабочей базы. Есть изменения ограничений и функций push-очереди; отсутствие удаления фотографий не отменяет необходимости проверки резервной копии и возможных блокировок таблиц.

## Порядок после отдельного разрешения

1. Получить доступ к существующему сервису Render и его БД. Сверить источник, ветку, автопубликацию, применённые миграции и переменные окружения без вывода секретов.
2. Создать резервную копию и проверить восстановление на отдельной тестовой базе. Проверить на ней переход с фактической рабочей схемы на новый релиз.
3. Для включения TOTP проверить наличие корректного `TOTP_ENCRYPTION_KEY` (32 случайных байта в base64). Уже существующий ключ не заменять. Без него 2FA остаётся недоступной. Отдельно проверить VAPID, если требуется включение web push.
4. Провести код через GitHub `alexey-panchenko-dev/Zentry-Chat`. Выпускать на существующем Render-сервисе из согласованного коммита; не включать постоянный auto-deploy без отдельного запроса.
5. После запуска проверить readiness, ревизию и возможности API, авторизацию, замену фотографии и её кэш. Использовать тестовые аккаунты без чтения чужих переписок.
6. При сбое не пытаться автоматически откатывать схему и не удалять новые таблицы. Сначала сверить совместимость прежней версии с расширенной схемой; восстановление рабочей БД из копии требует отдельного решения.

## Что требуется сейчас

Отдельное разрешение на обновление Render и применение подтверждённого набора миграций к production. До этого опубликованный frontend продолжает работать с прежним API, а подготовленный серверный релиз остаётся локальным.
